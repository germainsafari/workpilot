# WorkPilot Observability

## Architecture

```
workpilot-api container
  │  OTLP gRPC (localhost:4317)
  ▼
adot-collector sidecar  ──────────────────────► AWS X-Ray
  │  resourcedetection processor
  │  (injects ECS task/cluster/account metadata)
  └────────────────────────────────────────────► CloudWatch Logs
                                                 /workpilot/api/traces
```

All traces carry X-Ray-compatible trace IDs (generated by `AwsXRayIdGenerator`) and are propagated via the `X-Amzn-Trace-Id` header so ALB and downstream services join the same trace.

## Key spans and attributes

| Span name | Emitted by | Key attributes |
|-----------|-----------|----------------|
| `run.execute` | `run_service.py` | `workpilot.run_id`, `workpilot.trace_id`, `workpilot.workflow_id`, `workpilot.run.status`, `workpilot.run.steps` |
| `step.completed` event | `run_service.py` | `step_id`, `status` |
| HTTP request spans | FastAPI instrumentor | `http.method`, `http.route`, `http.status_code` |
| DB query spans | SQLAlchemy instrumentor | `db.statement`, `db.system` |

## Enabling locally

```bash
# Run ADOT collector in Docker (uses infra/adot-config.yaml)
docker run --rm -p 4317:4317 -p 4318:4318 \
  -v $(pwd)/infra/adot-config.yaml:/etc/otel/config.yaml \
  -e AWS_REGION=eu-central-1 \
  public.ecr.aws/aws-observability/aws-otel-collector:latest \
  --config /etc/otel/config.yaml

# Start API with OTel on
WORKPILOT_OTEL_ENABLED=true uvicorn app.main:app --reload
```

AWS credentials must allow `xray:PutTraceSegments` and `logs:PutLogEvents`.

## Enabling in ECS (Fargate)

The Terraform task definition in [`infra/ecs.tf`](../infra/ecs.tf) includes an `adot-collector` sidecar container that mounts the config from a bind mount. Set `WORKPILOT_OTEL_ENABLED=true` in the task environment (or via Secrets Manager) to activate the SDK.

The ECS task role already grants `xray:PutTraceSegments`, `xray:PutTelemetryRecords`, and `logs:PutLogEvents` — see [`infra/iam.tf`](../infra/iam.tf).

## CloudWatch dashboard

A basic Markdown dashboard JSON is not included, but the recommended approach is to use the X-Ray Service Map in the AWS console. Filter by `workpilot.workflow_id` or `workpilot.run_id` to trace individual automation runs end-to-end.

## Adding spans to new code

```python
from app.telemetry import get_tracer

tracer = get_tracer("workpilot.my_module")

async def my_function(run_id: str) -> None:
    with tracer.start_as_current_span("my_function") as span:
        span.set_attribute("workpilot.run_id", run_id)
        # ... work ...
```

When `WORKPILOT_OTEL_ENABLED=false` (the default), `get_tracer` returns a no-op shim so tests never need AWS credentials.
